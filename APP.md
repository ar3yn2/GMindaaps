# GM AAPS — Руководство пользователя

## Установка двух версий рядом

GM AAPS использует package name `app.gmaaps`, оригинальный AAPS использует `app.aaps`. 
Они **не конфликтуют** и могут стоять одновременно на одном устройстве.

```powershell
# Установить GM AAPS (основной)
adb install -r "E:\AAPS\aaps4\app\build\outputs\apk\full\debug\app-full-debug.apk"

# Установить GM AAPS Client 2 на телефон
adb install -r "E:\AAPS\aaps4\app\build\outputs\apk\aapsclient2\debug\app-aapsclient2-debug.apk"

# Оригинальный AAPS можно не трогать — он продолжит работать
```

## AI Profile Analyzer — Настройка и использование

### Включение плагина

1. Откройте GM AAPS → **Settings** (Настройки)
2. Найдите раздел **AI Profile Analyzer**
3. Переключите тумблер **Enable AI Profile Analyzer** в положение ON
4. Приложение может вылететь при первом включении — это нормально, перезапустите

### Настройка API ключа

Если у вас есть доступ к внешнему AI API:

1. Settings → AI Profile Analyzer → **API URL**
2. Вставьте свой endpoint (например `https://api.yourai.com/v1/analyze`)
3. Settings → AI Profile Analyzer → **API Key** — вставьте ваш ключ
4. Если API ключ пустой — используется локальная эвристика (работает без интернета)

### Уровень агрессивности

Settings → AI Profile Analyzer → **Aggressiveness**:

| Уровень | ISF shift | Basal shift | Мин. уверенность | Max spike'ов/день | Описание |
|---------|-----------|-------------|-------------------|--------------------|----------|
| **CALM** | 5% | 5% | 90% | 1 | Conservативный — только подтверждённые изменения |
| **MODERATE** (Recommended) | 15% | 10% | 75% | 2 | Баланс между реактивностью и стабильностью |
| **AGGRESSIVE** | 25% | 20% | 60% | 4 | Агрессивный — быстро реагирует на изменения |

### Период анализа

Settings → AI Profile Analyzer → **Analysis Days**:
- **7 дней** — стандартный период, быстрее реагирует на изменения
- **30 дней** — более стабильная статистика, медленнее адаптируется

Рекомендуется начать с 7 дней для быстрой настройки.

### Как работает AI анализатор

#### Шаг 1: Сбор данных (каждые 6 часов)
AI модуль собирает данные из базы AAPS за указанный период:
- Показания CGM (глюкоза)
- Болюсы (insulin bolus)
- Углеводы (carbs logged)

#### Шаг 2: Анализ статистики
Рассчитываются метрики:
- Средний BG и медиана за период
- CV% (вариабельность глюкозы) —越低越好
- TIR/TAR/TBR (время в/выше/ниже диапазона)
- Средняя инсулин/углевод нагрузка на сутки

#### Шаг 3: Детекция spike'ов
Для каждого скачка BG > threshold проверяется:
- Был ли bolus в течение [-90min .. +30min] от пика?
- Были ли carbs в том же окне?

**Защита от ложных срабатываний:**
- Если за сутки 1-2 spike'а без углеводов — **не предлагается изменение** (возможно, пропущенные углеводы)
- Если > maxSpikesPerDay необъяснимых скачков подряд — **предлагается корректировка профиля**

#### Шаг 4: Генерация рекомендации
При высоком confidence score AI предлагает:
- Сдвиг ISF на X% (insulin sensitivity factor)
- Сдвиг basal rate на Y% (базальный инсулин)

#### Шаг 5: Применение или отклонение
Пользователь видит уведомление с рекомендацией:
- ✅ **Apply** — применить рекомендованные изменения к профилю
- ❌ **Dismiss** — пропустить текущую рекомендацию

### Примеры работы

#### Сценарий 1: Стабильная глюкоза
```
7 дней данных → средний BG 140 mg/dL, CV% 28%, TIR 85%
→ AI не находит аномалий → рекомендаций нет ✓
```

#### Сценарий 2: Повышение среднего BG за неделю
```
Последние 7 дней → средний BG вырос с 130 до 165 mg/dL
2 необъяснимых spike'а подряд
→ AI предлагает: ISF -15%, Basal +10%
→ Пользователь подтверждает → профиль обновлён ✓
```

#### Сценарий 3: Один резкий скачок (защита)
```
За сутки один BG выскочил до 280 mg/dL
Нет bolus/carbs в окне 90min
→ При CALM/MODERATE: spike count = 1 < maxSpikesPerDay → **не предлагается изменение** ✓
→ При AGGRESSIVE: spike count = 1 < 4 → также не предлагается ✓
```

#### Сценарий 4: Резкие изменения спустя день
```
Вчера: нормальная статистика
Сегодня: 3+ необъяснимых spike'а за сутки
→ allowSameDayCorrection=true → AI предлагает корректировку даже в тот же день ✓
→ allowSameDayCorrection=false → ждёт следующего цикла (6 часов) ✓
```

### Логи и отладка

Если приложение вылетает при переключении тумблера:
1. Проверьте, что `AiProfileBindings.kt` существует в `app/src/main/kotlin/app/gmaaps/di/metro/`
2. Перезапустите приложение полностью (удалите данные: Settings → Apps → GM AAPS → Clear Data)
3. Попробуйте включить снова

### Локальная эвристика (без API ключа)

Если API URL/ключ пустой, AI модуль использует встроенную логику:
- Анализирует CV% и тренд BG
- Если CV% > 40% → рекомендация снизить basal на 10%
- Если средний BG растёт более чем на 20 mg/dL за неделю → рекомендация увеличить ISF на 10%
- Работает полностью офлайн, без интернета

## Обновление приложения

```powershell
# Переустановка с заменой (сохранит настройки)
adb install -r "путь\к\new\app-full-debug.apk"

# Полная переустановка (удалит данные)
adb uninstall app.gmaaps
adb install "путь\к\new\app-full-debug.apk"
```
